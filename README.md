# DocFlow — ИС автоматизации документооборота

Веб-приложение для управления документами организации: создание, согласование, утверждение и отклонение документов с разграничением прав доступа.

## Технологии

- **Backend:** Node.js, Express
- **База данных:** SQLite (`better-sqlite3`)
- **Шаблоны:** EJS
- **Авторизация:** express-session, bcrypt

## Запуск

```bash
npm install
npm start
```

Приложение откроется по адресу: **http://localhost:3000**

При первом запуске автоматически создаётся база данных `data/docflow.db` и демо-данные.

## Учётные записи

| Email | Пароль | Роль |
|-------|--------|------|
| `admin@docflow.local` | `Admin123!` | Администратор |
| `user@docflow.local` | `User123!` | Пользователь |

Также доступна **регистрация** новых пользователей (роль `user`).

## Роли

### Пользователь (User)
- Просмотр своих документов и назначенных ему
- Создание и редактирование черновиков
- Отправка документа на согласование

### Администратор (Admin)
- Просмотр всех документов
- Утверждение / отклонение документов на согласовании
- Управление пользователями (роли, блокировка)
- Панель статистики

## Схема базы данных

- **users** — учётные записи (email, ФИО, роль, статус)
- **documents** — документы (номер, тип, статус, автор, исполнитель)
- **document_history** — история действий по документу

## Типы и статусы документов

**Типы:** входящий, исходящий, внутренний

**Статусы:** черновик → на согласовании → утверждён / отклонён

## Валидация через чекбоксы

На формах регистрации и создания документа можно включить правила проверки. Отмеченные правила проверяются на клиенте и на сервере.

| Правило | Описание |
|---------|----------|
| Email без номера телефона | Email не должен содержать 7+ цифр подряд |
| ФИО без цифр | Только буквы, пробелы и дефис |
| Надёжный пароль | Минимум 8 символов, буква и цифра |
| Пароли совпадают | Пароль и подтверждение должны совпадать |
| Формат номера документа | Шаблон `БУКВЫ-ГГГГ-NNN` (например `ВХ-2026-001`) |
| Текст без телефонов | Содержание без телефонных номеров |
| Заголовок от 5 символов | Минимальная длина заголовка |

## Деплой на Render

Проект подготовлен для [Render](https://render.com).

### Способ 1 — Blueprint (рекомендуется)

1. Загрузите репозиторий на **GitHub**.
2. В Render: **New → Blueprint** → подключите репозиторий.
3. Render прочитает [`render.yaml`](render.yaml) и создаст Web Service.

### Способ 2 — вручную

1. **New → Web Service** → подключите репозиторий.
2. Параметры:
   - **Runtime:** Node
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Health Check Path:** `/health`
3. Переменные окружения:

| Переменная | Значение |
|------------|----------|
| `NODE_ENV` | `production` |
| `SESSION_SECRET` | случайная длинная строка (Generate) — **рекомендуется**; без неё на Render приложение всё равно запустится |
| `DATA_DIR` | `/var/data` (только при подключённом Disk) |

4. **Disk** (опционально, платный план — данные сохраняются между деплоями):
   - Mount Path: `/var/data`
   - Size: 1 GB
   - Пример конфигурации: [`render.disk.yaml`](render.disk.yaml)

> На **Free**-плане без диска база создаётся в папке `data/` приложения и может сбрасываться при перезапуске.

### Версия Node.js

Используется **Node 20 LTS** (файлы `.node-version`, `engines` в `package.json`).  
Не поднимайте версию до 22+ без проверки — `better-sqlite3` может не собраться.

Если Render уже создан вручную, добавьте переменную окружения:

| `NODE_VERSION` | `20.18.0` |

### После деплоя

- Откройте URL вида `https://docflow-xxxx.onrender.com`
- Войдите: `admin@docflow.local` / `Admin123!`
- Проверка работоспособности: `https://ваш-url.onrender.com/health`

### Локальные переменные окружения

Скопируйте `.env.example` в `.env` и при необходимости измените значения.
